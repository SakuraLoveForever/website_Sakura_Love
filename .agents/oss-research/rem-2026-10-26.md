# 雷姆（Re:Zero）主题与角色素材调研

核验日期：2026-10-26（Asia/Shanghai）。范围：给 `website_Sakura_Love` 增加第 4 套设计风格「雷姆」。只做调研，未改动任何仓库文件；本报告为唯一写入。

核验方式：本环境 `web_fetch` 会把 `github.com` / `api.github.com` 解析成非公网 IP 而失败，全部改用 `curl`（GitHub REST API 未认证，搜索限流约 10 次/分钟，core API 60 次/小时）。Star 数、license、pushed_at 均为本次 GitHub Search API 返回值；色值均从仓库原始 CSS/配置/素材逐字节取，附 raw URL 供复核。

## 结论先行

1. **没有「高星 + 许可干净 + 雷姆专属」的网页主题**。雷姆相关的 web 主题最高只有 48★，且是 GPL 的看板娘挂件，不是完整站点主题。可行路线是：**视觉基线取 8.4k★ / Apache-2.0 的蓝色二次元主题 hexo-theme-butterfly（#49B1F5 家族），角色摆放方式取 GPL 的雷姆看板娘项目做「参考」**，本站仍用纯 CSS 变量落地，不引入任何依赖。
2. **GitHub 上没有可合法内置的雷姆 Cubism 4 Live2D 模型**。能搜到的雷姆模型全是同一个 **Cubism 2.1**（`remu.moc` + `.mtn`，`"version": "Live2D MoePet v1.1"`），本站 `index.html:555` 只加载 `pixi-live2d-display@0.4.0/dist/cubism4.min.js`，没有 Cubism 2 运行时；而且模型版权属于原作方，仓库的 GPL 授权无法覆盖美术资源。**不建议内置**。
3. **唯一许可明确、可直接放进仓库的「雷姆角色出现」方案 = Wikimedia Commons 上 CC0 的雷姆 cosplay 实拍照**（已逐张下载验证，见第 3 节），配 `assets/backgrounds/rem/` 现有机制即可，零新代码。
4. 二次元插画风立绘想「既好看又干净」的答案只有一个：**站长自备/委托绘制，或站内自绘几何 SVG 点缀**（蓝丝带、发饰、铃铛），不用别人的图。

**为什么不能直接放进 `assets/live2d/`：**

1. **格式不兼容。** `rem.json` 里 `"model": "remu.moc"`，是 Cubism 2.1。本站 `index.html:555` 引入的是 `https://cdn.jsdelivr.net/npm/pixi-live2d-display@0.4.0/dist/cubism4.min.js`；全仓 grep `live2d.min.js|l2d.min|Cubism2|cubism2` **零命中**，没有 Cubism 2 运行时。要跑起来必须再加 `live2d.min.js`（Live2D Cubism 2 Core，官方已停止提供、许可不可再分发），与「只用现成能用的」背道而驰。
2. **授权不成立。** 仓库的 GPL-2.0 只能覆盖作者自己写的 JS/CSS；`remu.moc` + 纹理会话是雷姆角色的美术资源，作者没有转授权利。三份仓库字节级相同的 `remu.moc` 说明是同一份来源翻录，不是独立创作。
3. **体积与工作量**不是瓶颈（约 950 KB），**兼容 + 版权**才是。若将来真要内置，必须先换到 Cubism 4 模型并拿到作者书面许可，届时还要重做 `items_pinned_to_model.json` / 水印参数等本站专属适配。

> 注：Cubism 2 的模型在 `pixi-live2d-display` 里是另一条 `cubism2` 构建路径，不是 `cubism4.min.js` 能加载的；不要以为换个 loader 就能读。

## 4. 最省事、最不踩版权坑的方案

**主题 = 抄色板 + 自写 CSS；角色 = CC0 照片进现有背景轮播 + 自绘几何 SVG 点缀；Live2D 不做。**

落地清单（都是既有机制，不需要新依赖）：

1. 主题：`script.js:16` 的 `styleMap` 增加 `rem: "design-rem"`；`themes.css` 增加 `body.design-rem { --canvas:#0d1420; --text:#e6f0fb; --primary:#6FB3E8; --surface-*:…; --hairline:rgba(160,192,248,.16) }`，其余沿用现有暗色结构。切换动画、首帧、`syncRootThemeTokens` 全部走现有两条路径，无需改。
2. 角色：`assets/backgrounds/rem/1.jpg`（CC0 婚纱雷姆，建议 1920 宽、`object-fit: cover`），再在 `script.js:49` 的 `bgFiles` 加 `rem:[…]`、`script.js:67` 的 `bgRoleOrder` 插入 `"rem"`（`bgCount` 自动派生）。角色选择器与音乐按现有 role 机制自动生效。
3. 主题点缀：自己画一个「蓝丝带 + 铃铛」或「雷姆发饰」SVG 作为 `.design-rem` 的角标/分隔线。几何图形不涉及角色著作权，也不会踩任何人。
4. 若一定要「二次元插画立绘」：站长自备或委托绘制，放 `assets/backgrounds/rem/`；**不要**把别人画的雷姆、也不要 GitHub 上的雷姆 PNG/模型打进仓库。

最小验证：切到「雷姆」后刷新仍是雷姆（`localStorage` 回退正常）、首屏不闪黑、三套旧主题无回归、354px–桌面无溢出、`assets/backgrounds/rem/` 缺图时回退 `"02"`（`setBg` 已有该逻辑）。

关键风险，按严重度：

1. **Live2D 雷姆模型全部是未授权翻录**，且是 Cubism 2.1，本站加载器是 Cubism 4 —— 双重不可行。
2. **任何雷姆插画/模型/PNG 都不是可再分发的公开素材**；GitHub 上那些仓库的 GPL/MIT 只覆盖代码。
3. **CC0 cosplay 是真人照片**：著作权 OK，但仍要避免暗示代言；审美上也不是动画立绘，需站长确认能接受。
4. 高星蓝色主题（butterfly，Apache-2.0）与本站技术栈完全不同，**只能抄色值和交互规则**，别搬 Stylus/Hexo 结构。

## 6. 落地记录（2026-10-26，实际实现）

最终采用「第 4 套风格 Rem Dark + hero 左侧雷姆角色卡」，与第 4 节的建议有一处刻意偏离：

- **色板**：按本报告实测的雷姆发色落地 —— `--primary #8fd0f4`、`--primary-strong #b6e4fb`、`--primary-on-dark #a0c0f8`（发色亮部）、`--rem-hair #a0c0f8`、`--canvas #0d1622`、`--surface-pearl #172335`、`--hairline #2c3e58`、`--panel-radius 18px`；发带粉 `--rem-ribbon #f2a7bd` 只用在 hero 的 eyebrow 上。蓝色基线取自 jerryc127/hexo-theme-butterfly 的 `--blue #49b1f5` 家族，均只抄色值，未搬任何 Stylus/Hexo 结构，也未引入依赖。
- **角色**：用 `assets/character/rem/rem-portrait.jpg`（720×900，4:5，约 119 KB）做 hero 角色卡，而**不是**第 3 节的 CC0 cosplay 实拍。原因：CC0 那几张是真人 coser（人格权 + 非动画立绘，观感差异大），本站是二次元个人主页；本次按用户「要有雷姆的角色」的要求选了插画。
- **授权边界（必读）**：这张插画是第三方同人作品，**不可再分发**。它只作为站长自用素材放在仓库里；如果把仓库公开或商用，需要替换成自备/委托绘制的图（把文件换掉即可，`img` 路径不变）。这也是没走 GitHub 那批 GPL 雷姆模型/PNG 的原因。
